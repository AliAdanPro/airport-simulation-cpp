# Smart Airport Operations Management System

A comprehensive, real-time simulation of a smart airport, implemented in C++17. This system utilizes advanced operating system concepts to manage airport resources, flight schedules, and emergency situations.

## Core Features

### 1. Advanced Scheduling (HMFQ-PPRA)
The system implementation uses the **Hierarchical Multilevel Feedback Queue with Preemptive Priority and Resource Awareness (HMFQ-PPRA)** algorithm to schedule airport operations.
- **5 Priority Queues**: Ranging from Emergency (Queue 0) to Low Priority (Queue 4).
- **Aging & Migration**: Prevents starvation by promoting older tasks.
- **Resource Awareness**: Checks runway/gate availability before scheduling.

### 2. Intelligent Memory Management (AWSC-PPC)
Data management is handled by the **Advanced Working Set Clock with Predictive Prefetching and Compression (AWSC-PPC)** algorthm.
- **Working Set Tracking**: Dynamically adjusts memory allocation based on process phases.
- **Predictive Prefetching**: Uses Markov chains to predict and pre-load likely next pages.
- **Adaptive Compression**: Compresses cold pages to save space during high load.
- **Thrashing Prevention**: Detects potential thrashing and automatically adjusts working sets.

### 3. Real-Time Simulation
- **Dynamic Dashboard**: Visualizes runways, gates, and flights in real-time.
- **Event System**: Handles weather changes, medical emergencies, and mechanical failures.
- **Financial Tracking**: Monitors revenue (fees) vs costs (fuel, staff, delays).

## File Structure

- **Core Infrastructure**
  - `main.cpp`: Entry point and main simulation loop.
  - `simulation.h/cpp`: Central engine coordinating all components.
  - `config.h`: Configuration constants (budget, capacities, timings).
  - `types.h`: Shared data structures, enums, and constants.

- **Systems**
  - `scheduler.h/cpp`: HMFQ-PPRA implementation.
  - `memory_manager.h/cpp`: AWSC-PPC implementation.
  - `data_manager.h/cpp`: Database abstraction layer.

- **Domains**
  - `aircraft.h/cpp`: Aircraft states and properties.
  - `ground_services.h/cpp`: Refueling, catering, cleaning logic.
  - `passenger.h/cpp`: Check-in, security, and boarding flows.
  - `crew.h/cpp`: Crew scheduling and fatigue management.
  - `crisis_manager.h/cpp`: Emergency and weather handling.
  - `display.h/cpp`: CLI dashboard rendering.

## Compilation (Linux)

This project relies on standard C++17 and the POSIX Threads (`pthread`) library.

```bash
# Compile all source files
g++ -std=c++17 -pthread -o airport *.cpp

# Run the simulation
./airport
```

## Compilation (Windows)

Note: This codebase is optimized for Linux/Unix environments. For Windows, use WSL (Windows Subsystem for Linux).

```cmd
# In WSL or Linux VM:
g++ -std=c++17 -pthread -lncurses -o airport *.cpp
./airport
```

## Usage

```bash
./airport [options]
```

**Options:**
- `-s <speed>` : Set simulation speed multiplier (default: 1.0). Use 10.0 for fast forward.
- `-t <seconds>` : Run for a specific duration and then exit.
- `-d` : Enable Demo Mode (triggers automated weather/emergency events).
- `-h` : Show help message.

**Runtime Controls:**
- `+` / `-` : Increase/Decrease simulation speed
- `p` : Pause/Resume simulation
- `q` : Quit simulation
- `Ctrl+C` : Clean shutdown

## Build Artifacts Note
- `.o` files: Object files generated during compilation. Safe to delete.
- `.gch` files: Precompiled header files (e.g., `types.h.gch`). Generated by GCC to speed up compilation. Safe to delete if you change header files or want a clean build.
